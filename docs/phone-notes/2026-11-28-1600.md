**Asked:** how strong the engine is; then measure 13×13 and 19×19 against KataGo, including the coach (expert).

**Found:** while measuring, the computer froze late in 13×13 games (around Go Coach's 80th move). Cause: the liberty counters in search.js (`libs`) and engine.js (`flood`) mark points with a number that goes up by one every count and is stored in 32-bit arrays. After about 3.7 minutes of total thinking on one board size (the cache is kept between games, so any games and analysis since the app opened count) the number passes the 32-bit limit, marks never match, and the count never ends: search.js loops for ever, engine.js runs out of memory. Both now clear their marks and start again just before the limit.

**Checked:** with the counter set just below the limit, the old search.js froze and the old engine.js crashed; the fixed ones played a move. `node test.js` passes (79 tests). Not tried in a browser.

**Measurement:** 72 games on 13×13 running (Medium vs 20k/15k, Hard vs 15k/10k, expert vs 10k/5k, 12 each, both colours), results in tools/katago/results/2026-11-28-13x13.jsonl; 19×19 next. In node the expert (coach) uses one core, so its result is a lower bound for the app, which uses every core.
